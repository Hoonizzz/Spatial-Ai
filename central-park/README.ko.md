# Central Park · Cost Distance

한국어 명세를 기반으로 구현한 설치 의존성 없는 웹 시뮬레이션입니다. Node.js 22 이상을 권장합니다.

## 실행

1. ZIP을 풀고 이 폴더에서 터미널을 엽니다.
2. `node server.mjs` 또는 `npm run dev`를 실행합니다.
3. 브라우저에서 `http://127.0.0.1:4173`에 접속합니다.

Windows에서는 `실행.cmd`를 두 번 클릭해도 됩니다. 서버는 이 PC에서만 접속 가능한 주소로 실행됩니다. HTML을 파일로 직접 열면 모듈/Worker 보안 제한 때문에 동작하지 않습니다.

설치할 패키지가 없으며 `npm install`도 필요하지 않습니다. 인터넷 연결은 실제 지도 데이터 취득에 필요합니다. 인터넷 없이도 앱을 열고 **예제로 살펴보기**를 누르면 합성 네트워크에서 전체 흐름을 확인할 수 있습니다. 예제는 실제 도로/정류장 또는 실제 길안내가 아닙니다.

## 사용

- A/B 옆 원을 누르고 지도를 클릭하거나 마커를 드래그합니다. 장소 목록, 경도·위도 직접 입력도 지원합니다.
- 기본 경로는 도보 포함 전체 이동거리를 최소화합니다. 주행 거리를 비용으로 바꾸어 탐색하지 않습니다.
- 회원 유형, 체중, 주행 속도, MET, 도보 한도, 정지 시간을 바꿉니다.
- kcal/USD 단위, 재생/일시정지/초기화, 재생 속도, 시간 슬라이더를 조작합니다.
- ‘요금 비교 경로 보기’로 정류장 쌍별 거리 최단·시간 최단 후보 중 가장 저렴한 후보를 겹쳐 봅니다. 전역 요금 동률 내 최단거리 탐색은 보장하지 않습니다.
- 결과 내보내기는 ZIP 하나를 만듭니다. `result.json`, `route.geojson`, `cumulative.csv`, `snapshot.json`이 포함됩니다.
- `snapshot.json`을 가져오면 원본 도로·경계·설정·정류장 가용성 시나리오를 다시 계산합니다. 가져온 상태는 ‘현재 상태 아님’으로 표시합니다.

## 구현

- `dist/engine.js`: UTM 18N 변환, 1km 범위 판정, 방향 그래프, 진입 간선 상태를 보존한 Dijkstra, 가상 간선 분할, 정류장 쌍 전수 탐색, MET·정수 cents 요금.
- `dist/data.js`: NYC Parks 공식 경계, Overpass OSM 도로, GBFS discovery와 정류장 상태, IndexedDB 캐시, SHA-256.
- `dist/worker.js`: UI와 분리된 그래프 작성/경로 계산.
- `dist/app.js`: 한국어 SVG 지도, A/B 편집, 경로 비교, 누적 비용 그래프와 시간 재생, 스냅샷 내보내기/가져오기.
- `dist/example.js`: 명시적으로 선택하는 합성 네트워크. 실제 연결 실패 시 자동으로 실시간 데이터를 대체하지 않습니다.
- `dist/zip.js`: 외부 의존성 없는 ZIP 작성.
- `server.mjs`: 로컬 정적 서버와 선택적 JSON API. 브라우저 계산과 같은 엔진을 사용합니다.

지도를 타일 없이 직접 렌더링하므로 지도 라이브러리·키가 필요하지 않습니다. Google 지도 첨부의 색상/공간 구도만 참조하며 원본 이미지를 타일로 재사용하지 않습니다. 외부 글꼴은 연결되지 않아도 시스템 글꼴로 표시합니다.

## 실제 데이터

- NYC Parks `enfh-gkve` / `gispropnum=M010`의 가장 큰 Central Park 본체 형상을 선택하고 공간 크기를 검사합니다.
- EPSG:32618에서 공원 또는 공원 경계로부터 1,000m 이내인 점을 범위로 판정합니다. 1km 확장은 둥근 선 결합을 갖는 SVG stroke와 동일한 거리 집합으로 표시합니다.
- OSM 실제 노드·도로·회전제한을 취득합니다. 일방통행, bicycle/access, 계단, 장벽, conditional 태그를 보수적으로 처리합니다. 공원 내부 주행은 East/West/Center Drive만 허용하고 반시계 방향을 적용합니다. 불확실한 공유 경로 및 복잡한 via-way 제한은 제외합니다.
- 모든 범위 내 유효 정류장 중 보행 네트워크 한도에 들어오는 출발/도착 쌍을 평가합니다. 최근접 k개로 제한하지 않습니다.
- GBFS 전기자전거 수를 전체 자전거 수로 추정하지 않습니다. 전기자전거 수가 알려지지 않으면 대여 후보에서 제외합니다. 300초 이상 지난 상태로 실시간 가능성을 주장하지 않습니다.
- 최초 도로 취득은 1–2분이 걸릴 수 있습니다. 이후 7일 브라우저 캐시를 사용합니다. Overpass 과부하 시 ‘실제 데이터 다시 연결’은 다른 공개 서버를 사용합니다.

## 요금

2026-10-28 공식 공개 안내 기준: 비회원 $4.99 + $0.41/min, 유효 Day Pass $0 + $0.41/min, Annual/All Access $0.27/min, Reduced Fare $0.14/min입니다. 전기자전거에 일반 자전거 무료 시간을 적용하지 않습니다. 대여 전체 분을 한 번 올림하고 세금·프로모션·개인 크레딧은 제외합니다. 맨해튼 내부 요금 상한은 적용하지 않습니다. 30/45분 초과는 미검증 장시간 규칙 경고를 표시합니다. Day Pass 새 구매비는 선택적으로 추가할 수 있습니다. 연간/월간 가입비는 기존 회원 증분요금에 더하지 않습니다.

## API (로컬 Node 서버)

- `GET /api/policies`
- `GET /api/area` — 최초 호출 시 실제 경계/도로를 가져와 `runtime/network.json`에 캐시합니다.
- `GET /api/stations`
- `POST /api/route`

```json
{"a":{"lon":-73.9819,"lat":40.7681},"b":{"lon":-73.9492,"lat":40.7967},"profile":"single_ride","settings":{"mass_kg":70,"ebike_met":4,"speed_kph":15,"walk_limit_m":800,"pause_min":0}}
```

API도 실제 네트워크 연결이 필요하며 미검증 외부 데이터 연결을 성공했다고 가정하지 않습니다. 정적 Sites 배포에서는 브라우저 Worker 엔진을 사용하며 Node API는 제공하지 않습니다. 브라우저는 외부 소스에 직접 연결하고 A/B 좌표는 외부 길찾기 서버에 전송하지 않습니다.

## 검증

`node --test tests/engine.test.mjs`

16개 검증: UTM 좌표, 요금/분 올림, 회원 상한 비적용, 패스 구매비 분리, gross/active kcal, 정류장 stale/재고/도크, 거리/시간 경로 차이, 일방통행, 간선 중간 투영, 금지회전, U-turn, 1km 범위, GBFS 누락값, 전체 여정, A=B/불가 상태, ZIP 헤더.

작성 환경에서는 16개 테스트 통과 및 JS 구문·HTML ID 연결 확인을 완료했습니다. **외부 DNS/소켓 제한으로 실제 데이터 취득, 브라우저 화면 QA, API 실시간 통합 검증, 원격 소스 푸시/배포는 완료하지 못했습니다.** 배포 URL을 성공한 결과로 제공하지 않습니다.

## 남은 명세 차이 / 운영 전 검증

이 구현은 연구용 실행 가능한 MVP입니다. 명세 전체의 운영 인수 완료를 주장하지 않습니다.

1. 실제 데이터 연결과 실제 브라우저 화면을 인터넷 가능한 환경에서 확인해야 합니다. 공식 API 스키마 변경이나 CORS/공개 Overpass 제한으로 연결이 실패할 수 있습니다.
2. 단순 도로 간선의 시작·끝·중간점으로 범위를 검사합니다. 모든 간선 형상을 엄밀한 경계로 분할하는 GIS 전처리와 사소한 1km 경계 통과 오차 검증이 남아 있습니다.
3. 경계는 공식 형상을 사용하지만 make-valid/전문 GIS 위상 수정은 적용하지 않습니다. 복잡한 via-way 회전 제한은 해당 from-way를 제외하는 보수적 처리입니다.
4. A/B·정류장은 50m 안의 도로 간선에 투영합니다. 거리·경로는 투영 지점 기준이며 원래 점과 투영점 사이의 보행 가능 연결/거리까지 보장하지 않습니다. 화면에 이를 표시합니다. 정류장이 분리된 보도 네트워크에 놓인 경우 다른 후보로 제외되거나 연결되지 않을 수 있습니다.
5. 현장 폐쇄·시간별 통행 허용·공유 경로·차량별 도크 호환성과 배터리는 운영자/현장 검증이 필요합니다. 낮은 재고와 도크 변동 때문에 도착 시 가용성을 보장하지 않습니다.
6. 실제 반납 실패를 자동 감지하지 않습니다. 반납 실패 시 추가 정지를 설정하거나 다른 도착역을 선택해 새로 비교할 수 있습니다. 실제 결제·대여·예약은 수행하지 않습니다.
7. 전역 최저요금의 모든 동률 경로 탐색, 다회 대여, 최소 kcal 탐색, 등비용 지도, 자유 주소 지오코딩, 출발 시각별 예측/폐쇄, 고도 보정은 미구현입니다. 외부 주소 전송 대신 장소 목록/좌표를 제공합니다.
8. 가격·30/45분 초과 과금·상한 자격·세금은 공개 안내와 운영자 견적으로 재확인한 뒤 실제 결제 수준의 정확성을 주장해야 합니다.
9. p95 2초는 실제 도로/장치에서 측정하지 않았습니다. 예제 1,768개 노드/7,034개 간선은 수십 ms 수준으로 계산됩니다.
