# 센트럴파크 Cost Distance 인터랙티브 시뮬레이션 기술 명세

버전 1.0 · 조사 기준일 2026-10-28 (America/New_York) · 구현 대상: 웹 · 언어: 한국어

## 1. 목적과 완료 범위

사용자가 시작점 A와 도착점 B를 지정하면, 센트럴파크와 경계 바깥 1,000m 영역에서 자전거 통행이 허용된 네트워크의 **거리 최단 경로**를 먼저 구한다. 그 경로를 이동하는 데 드는 사람의 추정 에너지(kcal)와 Citi Bike 전기자전거 이용료(USD)를 함께 시각화한다. 물리적 거리를 두 종류의 비용으로 읽는 실험이며, kcal와 USD를 더하거나 같은 단위로 환산하지 않는다.

산출물은 지도, A/B 편집, 도보 접근·전기자전거 주행·도보 이탈 경로, 누적 비용 애니메이션, 산출 근거 패널, 최단거리/최저요금 비교, 재현 가능한 결과 내보내기다. 이 문서는 구현 명세이며 실제 앱 또는 실측 주행 결과는 아니다.

핵심 입력은 A/B 두 개로 유지한다. 회원 유형·체중·속도·출발 시각 등은 기본값을 가진 접힌 설정 패널로 제공한다. 기본 회원 유형은 **비회원 단건**, 체중 70kg, 도보 4.8km/h, 주행 15km/h, 출발 시각은 조회 시각이다. 기본값은 사용자 신체나 실제 교통 상황을 의미하지 않는다.

## 3. 공간 범위와 합법 통행

### 3.1 경계

1. NYC Parks Properties에서 Central Park 본체 폴리곤을 선택한다. 이름만으로 무조건 결합하지 말고 공원 식별자·형상·원본 지도와 대조하여 선택 규칙을 고정한다.
2. WGS84 경계를 미터 단위 투영좌표계 **EPSG:32618**로 변환하고 형상 오류를 수정한다.
3. `study_area = buffer(park_polygon, 1000m)`로 정의한다. 중심점 반경 1km나 사각형 확장은 사용하지 않는다. 공원 내부도 포함한다.
4. 화면 좌표는 EPSG:4326 GeoJSON, 거리 계산은 투영좌표계 또는 검증된 측지 거리로 수행한다. EPSG:3857 지도 픽셀 거리로 비용을 계산하지 않는다.
5. 데이터 취득은 경계 밖 여유 영역까지 수행해 교차로 연결이 잘리지 않게 한다. 기본 경로는 study_area 내부로 제한한다. 범위 밖 우회가 있어야 연결되는 경우 `NO_ROUTE_WITHIN_STUDY_AREA`를 반환한다. 선택적 확장 검색은 별도 표시하며 기존 결과를 조용히 바꾸지 않는다.

### 3.2 방향·접근·차량 프로필

공원 Drives는 반시계 방향 일방통행이다. 일반 보행로와 잔디를 자전거 지름길로 쓰지 않는다. 96th Street 및 West 106th–108th Streets의 표시된 공유 경로는 위치와 전기자전거 허용 여부를 별도로 검증한다. 자동차용 횡단도로가 보인다는 이유만으로 자전거 또는 공원 진출입 연결을 자동 승인하지 않는다. [Central Park 통행 규칙](https://www.centralparknyc.org/rules-regulations-permits)

현행 Drives 안내는 전기자전거 이용과 15mph 제한을 명시한다. 일반 규칙 페이지의 20mph 문구보다 전기자전거에 구체적인 제한을 적용한다. 기본 예측속도 15km/h는 제한속도 15mph(약 24.14km/h)보다 낮다. 공원 외부도 도로·차종·시간별 규칙을 확인한다. NYC DOT 페이지는 공원 Drives/greenways의 전기자전거 허용을 시범 운영으로 설명하므로 영구 허용으로 하드코딩하지 않는다. [Drives 안내](https://www.centralparknyc.org/drives), [NYC DOT 전기자전거 안내](https://www.nyc.gov/html/dot/html/bicyclists/ebikes.shtml)

그래프는 `walk`, `ebike_ride`, `bike_push` 모드를 구분한다. bicycle/access/oneway/oneway:bicycle, 차량별 허용, 회전제한, 진입 장벽, 계단, 공사·시간 제한, 교량·터널 높이 레벨을 처리한다. 평면에서 선이 교차해도 입체교차는 연결하지 않는다. 기본 자전거 구간은 승차 가능한 간선만 사용하고, 내려서 끄는 구간은 명시적 보조 모드로만 제공한다. 대여 중 끌거나 멈춘 시간도 과금 시간에 포함한다. 허용 여부가 불분명한 공원 연결은 검증 전 승차 그래프에서 제외한다.

통행 규칙은 `edge_id, mode, allowed, direction, valid_from, valid_to, source_url, checked_at, reason`을 가진 override 테이블로 관리한다. 현장 표지와 최신 공식 폐쇄 공지가 우선하며, OSM 태그만으로 합법성을 보장한다고 표시하지 않는다.

## 4. A/B와 정류장 경로의 엄밀한 정의

### 4.1 기본 서비스 모드

A/B는 실제 출발·도착 장소다. 임의의 위치에서 Citi Bike를 꺼내거나 반납할 수 없으므로 다음 여정을 계산한다.

`A → 도보 → 출발 정류장 S → 대여 → 합법 전기자전거 경로 → 반납 정류장 T → 도보 → B`

기본 접근 도보 한도는 각 끝 800m의 **보행 네트워크 거리**다. 이는 운영자 규칙이 아닌 제품 가정이다. 직선거리로 후보를 넓게 찾은 후 실제 보행 경로로 필터링한다. 한도를 늘릴 때 설정 변경을 표시한다. S=T는 기본적으로 제외하고 A=B이면 대여하지 않는 0 이동 결과를 반환한다.

실시간으로 사용 가능한 모든 후보 정류장 쌍에 대해 `L_walk(A,S) + L_ride(S,T) + L_walk(T,B)`가 최소인 여정을 선택한다. 동일하면 주행거리, 전체 시간, 정류장 ID 순으로 결정한다. **이 결과의 이름은 ‘도보 포함 최단 이동거리’**다. 선택된 S/T 사이 주행 경로도 미터 가중치로 최단이어야 한다. 후보를 최근접 k개로 제한하면 전역 최단이라고 부르지 않고 근사 결과로 표시한다. 작은 대상지에서는 한도 내 전체 후보를 평가하는 것을 기본으로 한다.

### 4.2 연구용 순수 자전거 모드

A/B를 정류장으로 직접 선택하면 `argmin Σ length_m`인 S→T 주행 경로를 표시한다. 임의 좌표를 승차 그래프에 투영해 순수 자전거 거리를 실험할 수도 있으나 이 경우 ‘가상 주행’으로 표시하며 해당 지점의 대여 가능성 또는 실제 Citi Bike 거래를 주장하지 않는다. 도보 포함 결과와 순수 자전거 최단 결과의 수치를 같은 이름으로 혼합하지 않는다.

### 4.3 최저요금 경로와의 차이

거리 최단 탐색의 간선 가중치는 미터다. 비용 계산은 그 뒤에 수행하며 kcal·USD·혼잡 가중치로 기본 경로를 바꾸지 않는다. 최저요금 비교는 **동일한 회원·정류장 상태·도보 한도·출발 시각·1회 대여 조건**에서 가능한 여정의 과금액을 최소화한다. USD 동률이면 전체 거리, 시간 순으로 선택한다. 걷기만 하는 무료 경로나 무제한 원거리 도보를 이 비교에 끼워 넣지 않는다.

신호가 많은 짧은 길은 더 긴 길보다 오래 걸릴 수 있으므로 최단거리와 최저요금은 다를 수 있다. 예: 가상 후보 R1=3.0km/16분, R2=3.5km/13분일 때 비회원 세전 요금은 각각 $11.55와 $10.32다. 이 값은 실제 A/B 계산 결과가 아니라 차이를 설명하는 예다.

일반 분당 선형요금에서는 고정 정류장 쌍의 최단시간 경로로 최소요금을 구할 수 있다. 분 올림으로 동률이 생기므로 해당 최소요금 구간 안에서 거리 동률해소가 필요하다. 상한·프로모션 등 비단조 정책을 켜면 최단시간 하나만 평가하지 않는다. 시간/거리 다중 라벨 탐색 또는 제한된 시간 상태 그래프로 종단 요금함수를 평가한다. 상한은 간선별로 나누어 Dijkstra 가중치로 넣지 않는다. 제한된 k개 대안만 평가한 경우 ‘후보 중 최저요금’으로 표시한다. 기본 MVP는 단일 대여만 지원하며 중간 반납·재대여 최적화는 범위 밖이다.

### 5.2 시간·올림·기본 공식

`rental_seconds`는 자전거가 도크에서 분리된 때부터 **정상 반납 완료**까지다. 신호대기, 대여 후 준비, 정지, 도크 탐색, 반납 시도 시간을 포함한다. A→S 및 T→B 도보는 포함하지 않는다. 앱의 타이머는 undock 시 시작하고 안전하게 잠겼을 때 끝난다. [시간 및 종료 규칙](https://help.citibikenyc.com/hc/en-us/articles/360032024912-How-long-can-I-keep-a-bike-out)

```text
t_rental = t_depart_setup + Σ(edge_length / edge_speed)
           + Σ(signal_or_turn_delay) + t_pause + t_dock_search + t_dock_finish
n = ceil(t_rental_seconds / 60)  # 유효 대여가 발생한 경우
base_usd = unlock_usd + ebike_rate_usd_per_min * n
```

분당 요금은 분 단위 올림이라는 공식 안내를 적용한다. 구간별로 올림 후 더하지 않고 **한 대여 전체를 한 번 올림**한다. 금액은 정수 cents 또는 Decimal로 계산한다. 유효 대여가 없는 0초 요청에는 잠금 해제비를 만들지 않는다. [전기자전거 올림 규칙](https://help.citibikenyc.com/hc/en-us/articles/360039406631-Riding-with-an-ebike)

단건 10분은 `$4.99 + 10 × $0.41 = $9.09`, 10분 1초는 `$9.50`다. Annual 10분은 `$2.70`, 30분은 `$8.10`이다. 후자는 아래 상한을 적용하지 않는 맨해튼 내부 기본값이다. 유효 Day Pass의 10분 증분요금은 `$4.10`, 새 구매까지 포함하면 `$29.10`이다. 멤버십 구매비를 매번 대여비로 더하지 않는다. 연회비 배분은 선택적으로 `239 / assumed_annual_trips`로 별도 표시하고 사용자가 정한 연간 횟수를 명시한다.

### 5.3 상한과 장시간 규칙: 확인 사실과 해석 구분

공식 전기자전거/Annual 페이지는 **45분 이하이며 Manhattan에 진입하거나 나가는** 회원 주행에 $5.40 상한을 안내한다. 본 대상지의 S/T는 모두 맨해튼 내부이므로 **기본적으로 상한을 적용하지 않는다**. ‘Manhattan 출발 또는 도착이면 무조건 상한’으로 구현하지 않는다. 지리 조건은 별도 policy predicate로 두고 외부 자치구 이동을 지원할 때 공식 결제 견적·고객지원으로 경계 조건을 검증한다. 적용 가능성이 확인된 경우에만 `min(rate*n, 5.40)`을 사용한다. [공식 상한 설명](https://citibikenyc.com/how-it-works/electric)

공개 페이지는 30/45분 초과 요금과 전기자전거 분당 요금의 관계를 충분히 일관되게 설명하지 않는다. Annual 안내는 45분 초과도 $0.27/min이라고 쓰며, Day Pass 페이지에는 일반 자전거와 차종 무관이라는 표현이 함께 있다. 따라서 **같은 분당 요금을 무조건 이중 가산하지 않는다**. 맨해튼 내부 기본 추정은 전 시간에 프로필별 전기자전거 단가를 1회 적용한다. 단, 기준시간을 초과하면 `LONG_RIDE_RULE_UNVERIFIED` 경고와 ‘기본 요금 추정’ 라벨을 반환한다. Reduced Fare의 초과 단가 전환도 별도 미확정 상태로 둔다. [Annual 설명](https://citibikenyc.com/pricing/annual), [Day Pass 설명](https://citibikenyc.com/pricing/day)

운영 전 29:59/30:00/30:01 및 44:59/45:00/45:01에 대해 운영자 앱의 요금 설명 또는 공식 지원 답변으로 정책을 확인하고 `overage_mode = none | replace_after_threshold | add_after_threshold`와 단가를 확정한다. 확인 전에는 해당 구간의 확정 청구액을 표시하지 않는다. 실제 청구와 일치한다는 출시는 이 검증을 통과해야 한다. 상한 대상의 45분 초과 시 상한 소멸/연장 방식 역시 확인 없이 외삽하지 않는다.

### 5.4 세금·예외

세금은 0%로 단정하지 않고 `tax_status=not_included`로 반환한다. 현재 세율·과세 대상·반올림을 검증한 세금 모듈을 붙이기 전에는 세후 금액을 표시하지 않는다. 프로모션, Bike Angels 크레딧, 연간 보너스, 무료 guest unlock, 저보조 모드 예외, 예약/일시정지 상품, 특별 반납·분실 비용은 기본값에서 제외한다. 계정 정보가 확보된 경우에만 별도 정책으로 적용하며 정류장에 일반 자전거가 없다는 사실만으로 무료 전기자전거를 추정하지 않는다. 긴 여행은 분실/초과 청구가 발생할 수 있으므로 비정상 장시간 결과를 일반 통근 견적으로 취급하지 않는다.

정책 파일에는 값뿐 아니라 `policy_id, currency, region, membership, verified_at, effective_from, source_urls, cap_predicate, overage_mode, tax_status, confidence`를 기록한다. GBFS `system_pricing_plans`가 존재하더라도 회원별 실제 요금이 완전하다고 가정하지 않는다. 공개 페이지 변경 감지는 검토 대상으로 처리하고 자동으로 계산식을 덮어쓰지 않는다.

## 6. kcal 모델

kcal는 **사람의 대사 에너지 추정량**이다. 전기 모터의 배터리 Wh 또는 도로 자체의 고정 속성이 아니다. 전기 보조 강도·체중·페달링·경사·속도에 따라 달라지므로 소수점 정밀도로 실측처럼 표현하지 않는다.

MVP는 구간 시간에 MET를 적용하는 설명 가능한 모델로 한다.

```text
gross_kcal_i = MET_i * 3.5 * mass_kg / 200 * duration_minutes_i
active_kcal_i = max(MET_i - 1, 0) * 3.5 * mass_kg / 200 * duration_minutes_i
total_kcal = Σ gross_kcal_i
```

기본 가정: 전기자전거 주행 MET 4.0, 도보 3.5, 서서 대기 1.3. 전기자전거 민감도 범위 3.0–6.0을 제공한다. 이 숫자는 본 시뮬레이션의 설정값이며 Citi Bike 실측 보정치 또는 임상 예측치가 아니다. 전기자전거 연구에서 중등도 이상 대사 활동이 보고되지만 장비·보조 수준에 따라 변한다. [전기보조 자전거 연구](https://pubmed.ncbi.nlm.nih.gov/22913003/)

예: 70kg, MET 4.0, 주행 10분이면 gross 49kcal, active 36.75kcal다. 기본 카드에는 전체 여정 gross 추정치를 반올림해 표시하고, 도보/주행/대기와 active 값을 펼쳐 볼 수 있게 한다. 정류장에서 대여 전 기다리는 시간은 kcal/전체 시간에는 포함할 수 있으나 대여 요금 시간에는 넣지 않는다.

경사 확장은 DEM을 따라 고도를 샘플링·평활화하고 실측으로 검증한 모델에만 연결한다. 임의 경사 가중치를 MET 식에 곱하고 정밀 모델이라고 부르지 않는다. 경사·페달 출력 모델과 MET 모델을 동시에 더해 이중 계산하지 않는다. 기본 모델에서는 경사가 별도 보정되지 않았음을 표시한다. 최소 kcal 경로 기능을 추가하더라도 기본 최단거리 경로는 유지한다.

## 7. 시간과 정류장 상태

주행 시간은 간선별 속도와 교차로 지연으로 산출한다. 기본 간선 속도 15km/h에서 시작하되 통행 제한, 표면, 급커브, 보행 혼잡에 따라 낮춘다. 신호 지연 기본 20초/해당 교차로, 대여 후 준비 30초, 반납 마무리 30초는 **모델 가정**으로 버전 관리한다. 동일 교차로 지연을 간선과 노드에서 중복 계상하지 않는다. 예측속도를 올려 법정 제한을 초과할 수 없게 한다.

정류장은 공식 [Citi Bike System Data](https://citibikenyc.com/system-data)의 GBFS를 이용한다. 확인한 discovery URL은 [GBFS 인덱스](https://gbfs.citibikenyc.com/gbfs/gbfs.json)이며 조회 시 version 1.1, ttl 60, `station_information`, `station_status`, `ebikes_at_stations`, `system_alerts` 등이 광고되어 있었다. URL·버전을 영구 고정하지 말고 인덱스에서 발견한다.

1. station_information과 station_status를 station_id로 결합한다. 버전별 adapter가 필드 존재·타입을 검사한다.
2. 출발은 설치·대여 가능 상태이면서 사용 가능한 전기자전거가 1대 이상인 역만 허용한다. 전체 자전거 수를 전기자전거 수로 대체하지 않는다.
3. 반납은 설치·반납 가능 상태이면서 해당 차량을 수용할 도크가 1개 이상인 역만 허용한다. vehicle별 호환성이 있으면 반영한다.
4. 공급자가 제공하는 전기자전거 세부·충전 정보의 의미를 확인한다. 단순 대수만으로 배터리 잔량·이동가능거리를 보장하지 않는다. 잔량이 없으면 `battery_range_unknown`을 표시한다.
5. 폴링은 feed ttl을 존중하고 백오프한다. 상태 나이는 공급자 타임스탬프와 수신시각을 함께 저장한다. 제품 기준 120초 초과는 stale, 300초 초과는 live 적합성 판정을 중지하고 캐시/시나리오 모드로 표시한다. 이 수치는 공급자 보장이 아닌 서비스 가정이다.
6. 출발 직전 재조회하고 역이 비거나 가득 차면 다음 후보로 재계산한다. 도착 시 도크가 남아 있을 것이라는 보장은 없다. 기본 결과는 ‘조회 시점 상태에서 가능한 예상 경로’다.
7. 반납 실패 시 타이머가 계속 흐른다. 대체역까지 추가 주행과 반납 시간이 USD·kcal에 누적된다. 실패한 반납 시도에서 새 잠금 해제비를 만들지 않는다.

API 실패 시 역을 임의로 채우지 않는다. 재현용 저장 스냅샷은 ‘저장된 시나리오’ 배지와 시각을 명시한다. e-bike 또는 도크가 없으면 `NO_EBIKE`, `NO_DOCK`, `NO_WALK_ACCESS` 등 원인을 구분한다. 사용자에게 재검색/도보 한도 확대를 제공한다.

## 8. 시각화와 조작

지도는 공원 연녹색, 물 파랑, 도시 도로 중성색으로 구성한다. 공원 외곽과 1km 버퍼를 별도 선으로 표시한다. 원본 빨간 마크업을 합법 경로처럼 표시하지 않는다. A/B는 클릭·드래그·주소 검색·좌표 입력으로 편집하고 바뀔 때 300ms 지연 후 계산한다. 검색 서비스 사용 조건과 입력 좌표의 외부 전송 여부를 밝힌다.

| 요소 | 동작 |
|---|---|
| 기본 경로 | 실선 주행, 점선 도보, 화살표 방향; 선택 S/T와 상태 시각 표시 |
| kcal 모드 | 구간 kcal/km 색상과 누적 kcal 그래프를 분리; 단위·범례 고정 |
| USD 모드 | 이동선 색상만으로 표현하지 않고 분 단위 계단형 누적 요금 그래프 제공 |
| 애니메이션 | 시작/일시정지/초기화/속도 조절; 재생속도는 예측시간·요금을 변경하지 않음 |
| 결과 카드 | 도보/주행/전체 km, 대여/전체 분, kcal 추정 범위, 세전 USD, 이용권 구매비 별도 |
| 비교 | 기본 최단거리와 최저요금 대안을 동시에 표시; 차이 km/분/kcal/USD |
| 근거 패널 | 회원, 체중, MET, 시간 가정, 요금 검증일, 출처, 정류장 스냅샷, 미확정 규칙 |

USD 누적 그래프는 unlock 직후 고정비가 생기고 청구 분 경계에서 상승한다. 목적지 B 도착이 아니라 T 반납 성공 시 과금이 끝난다. 0→대여 순간의 경계 처리를 명시한다. kcal는 계산된 구간 시간에 따라 누적한다. 두 그래프를 같은 축 단위로 그리지 않는다. 범례 없는 무지개 색상, 식품·커피 개수처럼 개인차가 큰 환산은 기본에서 제외한다.

A를 고정한 등비용 지도는 확장 기능이다. kcal는 네트워크 누적값, USD는 정류장 접근·대여·반납을 포함한 **완료 여정별** 평가로 만든다. 거리 원에 단가를 곱하거나 지역 전체를 연속 USD 표면으로 보간하지 않는다. 도달 불가·미검증 영역은 비워 둔다. 색상 외에 선 패턴·텍스트를 제공하고 키보드로 A/B와 슬라이더를 조작할 수 있게 한다.

## 10. 구현 아키텍처

권장 MVP 구성은 TypeScript/React + MapLibre GL JS 지도, Python/FastAPI 계산 API, GeoPandas/Shapely/pyproj 전처리, NetworkX 방향 그래프, PostgreSQL/PostGIS 저장소다. 단일 개발 환경은 GeoPackage/Parquet와 메모리 그래프로 시작해도 된다. 버전은 구현 시작 시 공식 문서를 확인한 뒤 잠금 파일로 고정한다. 본 명세는 특정 최신 버전 번호를 가정하지 않는다.

```text
공원/OSM/NYC 자료 → 배치 ETL → 통행 규칙 보정 → 버전 고정 그래프
GBFS → 수집·검증·캐시 → 정류장 상태 스냅샷
A/B + 설정 → 보행 접근 후보 → 거리 최단 탐색 → 시간 모델
          → 요금 정책 + kcal 모델 → 결과 GeoJSON/지표 → 지도·그래프
```

그래프의 주행 가중치는 길이 자체다. 일반 routing 서비스의 cycling 기본값이 안전성·도로 선호를 섞을 수 있으므로 그것을 ‘거리 최단’으로 그대로 쓰지 않는다. 자체 Dijkstra 또는 비음수 길이 가중 A*를 사용한다. A* 휴리스틱은 목표까지 직선 거리처럼 과대평가하지 않는 값으로 제한한다. 회전제한은 이전 간선 상태를 포함한 그래프로 처리한다. 간선 중간에 스냅할 때 원래 간선을 분할하고 길이·방향·속성을 보존한다.

데이터 구조:

```text
edges(id, from, to, geometry, length_m, modes, speed_kph,
      oneway, surface, restriction_ids, source_version)
turn_rules(in_edge, via_node, out_edge, mode, allowed, valid_time)
stations(id, geometry, installed, renting, returning, ebikes, docks,
         source_timestamp, received_at, schema_version)
fare_policies(id, profile, rate_cents, unlock_cents, pass_cents,
              cap_rule, overage_rule, verified_at, sources)
```

외부 API 키는 서버에 보관하고 회원 결제·잠금 해제·실제 예약은 이 시뮬레이션 범위에서 실행하지 않는다. 입력 좌표는 로그에 불필요하게 장기 보관하지 않는다.

### 10.1 API 계약

```json
{
  "a": {"lon": -73.9819, "lat": 40.7681},
  "b": {"lon": -73.9580, "lat": 40.8005},
  "mode": "station_trip",
  "objective": "shortest_total_distance",
  "profile": "single_ride",
  "settings": {"mass_kg": 70, "walk_limit_m": 800, "ebike_met": 4.0},
  "station_snapshot_id": "latest"
}
```

`POST /api/route`는 검증된 A/B, 선택 역, leg별 GeoJSON, 이동거리, 보행·주행·대기·대여 시간, kcal gross/active/범위, unlock/ride/pass/tax별 요금, 누적 시계열, warnings, graph/policy/model/snapshot 버전을 반환한다. 예시 좌표는 입력 형식 설명이며 실제 이용 가능 역·경로를 보장하지 않는다.

`GET /api/area`, `GET /api/stations`, `GET /api/policies`로 경계·상태·정책을 조회한다. 오류는 `OUTSIDE_AREA`, `INVALID_COORDINATE`, `SNAP_TOO_FAR`, `NO_ROUTE`, `NO_EBIKE`, `NO_DOCK`, `STALE_FEED`, `FARE_UNVERIFIED`로 구분한다. 스냅 거리 기본 50m를 넘으면 임의 연결하지 않고 사용자가 선택한 원래 지점을 유지한 채 오류를 설명한다. 길을 가로지르는 직선 스냅 연결은 보행 가능한 연결인지 확인한다.

## 11. 구축 순서와 인수 기준

1. **데이터 고정:** 공원·도로·자전거 시설 원본을 work 데이터 영역에 취득하고 manifest를 저장한다. 경계 선택과 1,000m 버퍼를 GIS에서 육안 검증한다.
2. **통행 그래프:** 보행과 e-bike 그래프를 분리하고 방향·회전·입체교차·금지로를 처리한다. 공원 Drives의 방향과 모든 진출입을 공식 지도/규칙과 대조한다.
3. **거리 엔진:** 정류장 없는 순수 S/T 길이 최단부터 구현한 뒤 보행 접근과 전체 후보 정류장 쌍 평가를 추가한다. 작은 수제 그래프로 전역 최소와 동률 규칙을 확인한다.
4. **상태 연동:** GBFS discovery/adapter와 stale 처리를 구현한다. 저장 스냅샷으로 재현 모드를 먼저 검증하고 live 모드를 연결한다.
5. **시간·비용:** 구간별 시간과 kcal, 분 올림 요금을 독립 함수로 작성한다. 정책 출처와 미확정 조건을 반환한다. 30/45분 경계와 cap 조건의 운영자 검증 기록을 남긴다.
6. **지도 UI:** A/B 편집, 도보/주행, 단위 전환, 애니메이션, 근거 패널을 연결한다. 재생·단위 전환 시 경로/원본 수치가 바뀌지 않는지 확인한다.
7. **비교·배포:** 동일 조건의 최저요금 비교를 추가한다. 결과 JSON/GeoJSON/누적 CSV를 내려받게 하고 그래프·정책·스냅샷 버전으로 재실행 가능하게 한다.

필수 검증 사례:

| 사례 | 기대 결과 |
|---|---|
| 루프 역방향 A/B | 반시계 방향 준수, 유클리드 지름길·역주행 없음 |
| 저수지·잔디·보행로 횡단 | 승차 간선 제외, 불가능하면 명시 오류 |
| 교차 도로/터널 | 높이 레벨이 다르면 연결되지 않음 |
| 여러 역 후보 | 최근접 역만 고르는 결과보다 전체 목적함수 최소임을 확인 |
| 10:00 vs 10:01 단건 | 세전 $9.09 vs $9.50; 간선별 올림 없음 |
| Annual 30분 맨해튼 내부 | 기본 $8.10; $5.40 자동 상한 금지 |
| 30/45분 경계 | 올림·초과정책·미검증 표시가 정책 fixture와 일치 |
| 70kg/MET4/10분 | gross 49, active 36.75 kcal |
| 도크 만석·반납 실패 | 대체 역까지 대여시간과 요금 계속 누적 |
| 전기자전거 0대/오래된 피드 | 불가능/상태 미확정; 가짜 live 성공 없음 |
| A=B/범위 밖/경로 단절 | 0 이동 또는 사유별 오류; 유효하지 않은 대여비 없음 |
| 최단거리 vs 최저요금 | 목적함수와 차이를 표시; 근사 탐색은 근사 라벨 |

수용 기준은 위 사례 통과, 정상 사례의 재현 가능한 경로/비용, 한국어 단위·가정 표시, 공식 출처 링크와 검증일 표시다. 성능 목표는 고정 그래프·캐시 상태에서 A/B 변경 후 p95 2초 이내로 설정하되 실제 장치/후보 역 수를 기록해 측정한다. 실패 시 후보를 줄여 최단 보장을 조용히 포기하지 말고 계산 대기 또는 명시적 근사 모드로 전환한다.

## 12. 출시 전 남은 검증 항목

- 해당 날짜의 공원 e-bike 허용 범위·임시 폐쇄·시간 제한을 최신 공식 안내 및 현장 표지와 대조한다.
- 상한의 자치구 경계 조건, 45분 초과 상한 처리, 프로필별 장시간 전기자전거 과금의 교체/추가 여부를 공식 결제 설명 또는 운영자 답변으로 확정한다.
- 세후 총액을 제공하려면 적용 세금과 반올림을 검증한다. 미검증 상태에서는 세전 추정으로 제공한다.
- GBFS 필드가 실제로 사용 가능한 e-bike 및 호환 도크를 뜻하는지 확인하고, 배터리 정보가 없을 때의 한계를 UI에 표시한다.
- 기본 MET·속도·대기시간은 모델 가정이다. 실측 보정 전에는 ‘소모 열량 측정’이나 ‘정확한 청구액’으로 표현하지 않는다.

이 항목들은 문서 작성의 미완료가 아니라 실제 결제 수준의 일치도와 현장 통행 보장을 위해 구현자가 수행해야 하는 운영 검증 조건이다. MVP는 명시된 범위에서 거리 최단 경로와 투명한 비용 추정을 제공한다.
